# Read-Back Verification

## Purpose
"Done" is the most lied-about word in automation. This skill makes setup claims checkable.

## The rule
Nothing counts as set up until it has been read back. After creating a job, watch, reminder, or integration:
- Verify it in the roster the same run (list it back), with its end date or window attached, before recording it as created anywhere.
- A recurring job that feeds a visible surface names its write-back path in the same step that creates it — where its output lands, and how you'll know it arrived.
- Any other future step (a reply to wait for, a delivery, a renewal, a check-back) gets a tracked item with a next-check date and an end condition. If it's truly done, say so in one line.

## The principle
A claim about the future ("it will run daily") is a status claim about the present ("it is configured to run daily") — and status claims need primary records. The roster listing is the primary record. "I created it" is a story; the listing is the fact.
