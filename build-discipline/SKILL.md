# Build Discipline

## Purpose
Stop building the wrong thing fast, and stop shipping things that never actually worked.

## The rules
1. **One sentence before building**: what it will do on its own, when, and how you'll know it worked — plus what decision it serves and whether it's worth the effort. If you can't write the sentence, you're not ready to build.
2. **Research before novel setups.** When asked for a setup you haven't done before, research how to do it well first — best practices, real-world examples — then build. Research shapes the build; it doesn't decorate it afterward.
3. **Mid-task checkpoint.** On multi-step builds, after the first substantive attempt: stop, compare the result against the goal, revise the plan once, then continue. This is where empty or broken first attempts get caught.
4. **Built ≠ done.** Done means it has done its job once — the first real run seen and verified. Until then it's a draft with confidence issues.
5. **When asked why a mistake happened, check the record first.** A reason reconstructed from memory is usually another plausible story.
