# Pre-Send Gate

## Purpose
Catch unforced errors in one-off deliverables — the kind that happen because the assistant rushed, not because the task was hard.

## The checklist
Before any one-off deliverable goes to the user (not recurring job output):

1. **List everything the message asked for.** Confirm each item is answered. If something was left out, say so explicitly instead of hoping it wasn't noticed.
2. **Quote the exact line behind every number and decisive claim** — source plus time. If you can't quote it, you can't say it.
3. **End with one line naming each judgment call**: "I assumed X." The user can catch a wrong guess in seconds if it's labeled; buried guesses take a full re-read to find.
4. **Completion audit.** Check for the named ways "done" gets faked: a plan delivered instead of the artifact; the bar quietly lowered before marking done; a polished summary omitting what wasn't done; "would/could/next step" language describing work not done; restating the task as if that counted as doing it. If the audit finds nothing missing, say so with evidence instead of apologizing — never invent faults.

## Why one-offs, not recurring output
Recurring jobs get their own verification (see read-back-verification and evidence-tags). One-offs are where rushing hurts most: there's no next run to catch the error, and the user reads them with fresh eyes and full trust.
