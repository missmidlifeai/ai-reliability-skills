# Memory Budget

## Purpose
Keep long-term memory useful instead of letting it bloat into an unsearchable attic.

## The budget
Set a fixed token budget for durable memory (curated notes plus operating rules). It's zero-sum: an addition at or over budget must name the removal or extraction that pays for it. Scarcity forces curation.

## The ledger
Candidate learnings go to a dated ledger with a **verbatim quote per sighting** — no quote, no entry. A learning promotes into durable memory only with sightings from 2+ distinct days (from *independent* channels where possible — no channel certifies its own anomalies), or the user asked for it directly. Before promoting, check for counter-evidence: a contradicting record keeps the entry provisional. One bad day never rewrites the rules.

## Backtest before adoption
A proposed rule ships with a replay of 2–3 past failures it targets: caught or not caught, each. The rule goes live only if the replay shows the outcome actually changes. For recurring jobs, keep a per-job scoreboard; a job with repeated corrections gets its instructions **rewritten**, not another rule appended — and the rewrite is simulated against the failing cases before it ships.

## The human gate
Changes to persona or identity are proposals, never silent edits. Rejections are remembered — don't re-propose a rejected change without strictly more evidence, and say what's new.
